// =============================================================================
//  DocRouter — App.OnStart  (COLLECTIONS DEMO VERSION)
//  Paste into App > OnStart.
//
//  Populates every collection in CLAUDE.md from literal seed rows, then sets
//  gblDrSeedVersion. Screens bind to these collections and never to a list, so
//  the SharePoint version replaces only this file's ClearCollect sources —
//  nothing downstream changes. See the SWAP POINT block below.
//
//  No IsEmpty guards, per the contract. OnStart runs once per launch and
//  ClearCollect is unconditional, so a reseed cannot drift from the schema.
//  gblDrSeedVersion records which shape was seeded, it does not gate the seed.
//
//  Dates are RELATIVE to Today() so the demo never goes stale. A fixed-date
//  seed shows everything as overdue after a fortnight on a buyer's desk.
// =============================================================================


// -----------------------------------------------------------------------------
//  APP IDENTITY
//  Aliases for the named formulas of the same meaning in App.Formulas. Kept
//  because CLAUDE.md names these as gbl* globals.
// -----------------------------------------------------------------------------



// -----------------------------------------------------------------------------
//  NAV STATE  (cmpSidebar)
//  cmpSidebar has AccessAppScope: true, so these four really are app globals.
//  The leading underscore is the component-scoped convention from house-rules
//  s1 and is load-bearing precisely because the scope is shared.
//
//  Initialised here rather than in a screen OnVisible so every screen inherits
//  them. The component's own documentation suggests a screen OnVisible; doing
//  it per screen would reset the nav on every navigation.
// -----------------------------------------------------------------------------

Set(_cmpNavIsExpanded, true);      // 260 wide; false collapses to 64
Set(_cmpNavSelID,      1);         // Home selected on load
Set(_cmpNavFooterMenu, false);     // footer flyout closed
ClearCollect(colNavExpanded, { ID: -1 });   // no parent groups expanded

// cmpFloatingActionButton speed dial state. The component owns every write to
// this, but the consumer must declare it: the FAB instance's own Height and
// Width formulas read _fabOpen, and those evaluate before the first tap.
Set(_fabOpen, false);

// There is deliberately no gblNavOpen and no mobile drawer. Desktop shows the
// sidebar, mobile shows the bottom nav plus a FAB for the primary action. A
// collapsible sidebar and a bottom nav are two navigation systems competing
// for the same destinations. The reference apps carry a drawer because they
// have no bottom nav; adopting their shell structure does not mean adopting
// their mobile navigation.


// -----------------------------------------------------------------------------
//  USER PREFERENCES  (colUserPrefs, from the UserPreferences list)
//
//  One row per user, keyed on UserEmail, indexed so the filter delegates.
//  Screens bind to colUserPrefs and never to the list.
//
//  SaveData/LoadData was prototyped here and REJECTED. It does not work in the
//  browser player: "There was a problem saving your data. Data can't be saved
//  in browser." DocRouter buyers run mostly in a browser, so the preference
//  would have failed silently for most of them. Do not reintroduce it.
//
//  First run creates the row rather than every screen guarding its reads. This
//  happens once per user, ever.
//
//  DELEGATION: Filter on UserEmail delegates because the column is indexed.
//  Patch and Collect on a single row are not delegation-sensitive.
// -----------------------------------------------------------------------------

//  COLLECTIONS DEMO: seeded in memory. There is no SharePoint here, so a
//  change made in Settings lives for the session and is gone on reload. See
//  the swap point note below for the SharePoint form.

// =============================================================================
//  ############  SHAREPOINT SWAP POINT — START  ############
//
//  Everything between this marker and the END marker is the collections-demo
//  data layer. It is the ONLY part of the app that differs between versions.
//
//  To build the SharePoint version, replace each ClearCollect below with its
//  list equivalent. The collection SHAPES must stay identical — every field
//  name, spelling, and type. A screen must not be able to tell which version
//  it is running on.
//
//    colConfig      ClearCollect(colConfig, Filter('Config', Active = true))
//    colRequests    ClearCollect(colRequests, Filter('Requests', IsDeleted = false))
//                   ...then AddColumns a Details record parsed from DetailsJson
//                   with ParseJSON, since screens read Details as a record.
//    colPhases      ClearCollect(colPhases, 'RequestPhases')
//    colAssignments ClearCollect(colAssignments, 'RequestAssignments')
//    colAudit       ClearCollect(colAudit, 'RequestAudit')
//    colComments      //    colDocuments   from the RequestDocuments library metadata
//    colTemplates   ClearCollect(colTemplates, Filter('WorkflowTemplates', Active = true))
//    colMetrics      //    nfStatusTable   a named formula, never a collection and never a list
//
//  DELEGATION — read before writing the SharePoint version:
//    RequestAssignments is the fastest growing list, fifteen or more rows per
//    request, and My Tasks queries it by AssigneeEmail plus StatusKey. A blanket
//    ClearCollect of the whole list silently truncates at the 2000 row limit.
//    Filter it server-side on the indexed columns (RequestKey, AssigneeEmail,
//    StatusKey) rather than pulling everything and filtering in memory.
//    Indexed and delegable: RequestKey, StatusKey, CategoryKey, DepartmentCode,
//    IsDeleted on Requests; AssignmentKey, RequestKey, PhaseKey, StatusKey,
//    AssigneeEmail on Assignments; RequestKey on every child list.
//
//  DATES: SharePoint returns UTC. Convert to local ON LOAD here so every
//  downstream comparison is local-to-local. Do not convert per screen or per row.
//
//  Site URL and list names are solution environment variables. Reading an
//  environment variable value directly in a formula forces premium — do not.
// =============================================================================

// ==========================================================
//  METRICS COMPUTED FROM THE DATA, not hardcoded. A stat tile
//  must never contradict the table under it. In the demo these
//  are in-memory collections, so CountRows carries no
//  delegation cost - the rule in CLAUDE.md is about SharePoint.
// ==========================================================
// ==========================================================
//  DEMO SCHEMA BRIDGE
//  Screens were written against the SharePoint column names
//  (ID, Created, Modified, DetailsJson, PhaseCount, Admins,
//  Active); the literal seed uses the demo's own names.
//
//  The seed lands in col*Seed and the REAL collection is
//  derived from it ONCE. Do not widen a collection from
//  itself: ClearCollect(colX, AddColumns(colX ...)) makes the
//  analyser infer colX as already containing the new columns,
//  which fails as "expected type Blank" with Patch and as
//  "column already exists" with AddColumns. Same cause, two
//  symptoms. Order matters: phases before requests, because
//  PhaseCount counts them.
// ==========================================================
ClearCollect(
    colPhases,
    AddColumns(
        colPhaseSeed As p,
        ID, p.PhaseOrder
    )
);
ClearCollect(
    colAssignments,
    AddColumns(
        colAsgSeed As a,
        ID, LookUp(colPhaseSeed, PhaseKey = a.PhaseKey).PhaseOrder * 100 + a.AssignmentOrder
    )
);
ClearCollect(
    colRequests,
    AddColumns(
        colReqSeed As r,
        ID,          Value(Right(r.RequestKey, 6)),
        Created,     r.CreatedDate,
        Modified,    r.LastModified,
        DetailsJson, JSON(r.Details),
        PhaseCount,  CountRows(Filter(colPhaseSeed, RequestKey = r.RequestKey))
    )
);
ClearCollect(
    colTemplates,
    AddColumns(
        colTplSeed As x,
        Active, true
    )
);


// The col*Seed tables have served their purpose: the real
// collections are derived above. Holding both doubles the
// memory for no reader.
ClearCollect(colReqPristine,   colRequests);
ClearCollect(colPhasePristine, colPhases);
ClearCollect(colAsgPristine,   colAssignments);
ClearCollect(colAuditPristine, colAudit);
ClearCollect(colTplPristine,   colTemplates);

Clear(colReqSeed); Clear(colPhaseSeed); Clear(colAsgSeed); Clear(colTplSeed);
